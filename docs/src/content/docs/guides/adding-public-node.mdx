This guide walks through adding a VM/VPS/root server/Droplet with a static IP from your Mac: create the VM, prepare SSH, fill inventory and open firewall rules.

The example uses inventory slug **`dev`** (for you, it could be `prod`/`staging`/`whatever` you like to call your environment, just `dev`) and host name **`static-1`**. 

Wherever you will see `PROVIDER=<slug>` replace it with your inventory slug and paths accordingly, e.g., `PROVIDER=prod` for production.

:::note[What this guide does not cover]

- **Lima guests** (`node_lima_guest`)
- **Home-lab roaming** (dynamic IP + Cloudflare Tunnel)
  :::

## Before you start

You must be arriving here from [Get started locally](/start-here/get-started) or [Deploy to production](/start-here/deploy-to-production)

Read `project` from `config.yml` (currently `example`). In examples below, `<project>` is that value and `<provider>` is your inventory slug (here `dev` for local, `prod` for production, or `anything` you like to call your environment).

Unsurprisingly, inventory slugs are found in `inventories/{slug}` folder.

Our objective is to complete the `inventories/<slug>/hosts.yml`, for `dev` it would be `inventories/dev/hosts.yml`:

```yaml
---
all:
  children:
    controller:
      hosts:
        localhost:
          ansible_connection: local
    deployment:
      hosts:
        static-1:
          wireguard_endpoint: "xxx.xxx.xxx.xxx" # Public IP of the VM with static IP
          ssh_host_ed25519_sha256: "SHA256:0f37...2ed230"
          wireguard_address: 10.217.80.11
        roaming-1:
          wireguard_roaming: true
          node_lima_guest: true
          node_host_architecture: aarch64
          ssh_host_ed25519_sha256: "SHA256:FILLED_AUTOMATICALLY_FOR_DEV"
          wireguard_address: 10.217.80.21
    wireguard_nodes:
      children:
        deployment: {}
```

## Step 1: Operator SSH key

On your Mac, create an Ed25519 key with an **empty passphrase**. Store both files in your password manager.

<Tabs syncKey="pkg">
<TabItem label="dev">

```sh
ssh-keygen -t ed25519 -a 100 \
  -f ~/.ssh/example-dev 
  -C "example dev"

ssh-add ~/.ssh/example-dev
pbcopy < ~/.ssh/example-dev.pub
```

</TabItem>
<TabItem label="Template">

```sh
ssh-keygen -t ed25519 -a 100 \
  -f ~/.ssh/<project>-<provider> \
  -C "<project> <provider>"

ssh-add ~/.ssh/<project>-<provider>
pbcopy < ~/.ssh/<project>-<provider>.pub
```

</TabItem>
</Tabs>

Inventory will reference this key as `~/.ssh/example-dev` via `ssh_private_key_file` in group vars.

**Important:** We will need the last line in Step 3.

## Step 2: Create the VM

In your cloud provider console:

1. Create a **Ubuntu Server 26.04** **amd64** (`x86_64`) on your favourite cloud provider. arm64 may/may not work, but we have not tested it.
2. Attach a **public IPv4** (or a stable DNS name you will put in inventory).
3. Do **not** rely on this automation to create the server or provider firewall rules—you configure those yourself.

Note the public IP (example format `xxx.xxx.xxx.xxx`).

## Step 3: Prepare the node (console or provider SSH)

On the new VM, create the inventory SSH user (example `ops`), install the Mac public key, and grant passwordless sudo:

```sh
sudo adduser --disabled-password --gecos '' ops
sudo install -d -o ops -g ops -m 0700 /home/ops/.ssh
sudo tee /home/ops/.ssh/authorized_keys >/dev/null
```

Paste the public key from the clipboard (from Step 1), press <Kbd mac="Control+D" windows="Control+D" />, then:

```sh
sudo chown ops:ops /home/ops/.ssh/authorized_keys
sudo chmod 600 /home/ops/.ssh/authorized_keys
printf '%s\n' 'ops ALL=(ALL) NOPASSWD:ALL' | \
  sudo tee /etc/sudoers.d/90-sc-ops >/dev/null
sudo chmod 440 /etc/sudoers.d/90-sc-ops
sudo visudo -cf /etc/sudoers.d/90-sc-ops
sudo -u ops sudo -n true
```

`visudo -cf` should report `parsed OK`.

## Step 4 — Verify the operator key

On your Mac:

```sh
ssh-keygen -lf ~/.ssh/example-dev.pub
```

On the new VM:

```sh
sudo ssh-keygen -lf /home/ops/.ssh/authorized_keys
```

The `SHA256:…` lines must match.

## Step 5 — Record the VM/server's fingerprint

On the VM:

```sh
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

# Sample output: 256 SHA256:pRR2cezc6UOTGq+vTrVwPFCFKlHRKuuV/OL/9/c3e+M root@whatever-server (ED25519)
```

Copy the full `SHA256:pRR...e+M` value into your password manager. You will paste it into inventory as `ssh_host_ed25519_sha256` (this is the **VM/server's** fingerprint).

## Step 6 — Fill inventory on the Mac

Remember, our objective was to complete the `inventories/<slug>/hosts.yml`, for `dev` it would be `inventories/dev/hosts.yml` -- now you can do that:

```yaml
...
static-1:
  wireguard_endpoint: "159.203.27.69"         # your public IP from Step 2
  ssh_host_ed25519_sha256: "SHA256:pRR...e+M" # your fingerprint from Step 5
  wireguard_address: 10.217.80.11             # your mesh IP (always `.11` for the first node)
...
```

To add another public node, duplicate the block as `static-2`, assign the next mesh IP (e.g. `.12`), and run `task up PROVIDER=<slug>` again.

## Step 7 — Cloud provider firewall

On the cloud provider (or host) firewall for this VM:

| Phase          | Rule                                                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Before setup      | Allow inbound **TCP 22** from your Mac’s current public `/32`                                                                                       |
| After setup | Allow inbound **UDP 51830** from peers that will dial this hub (if you will add roaming nodes later, open UDP 51830 broadly—not only the Mac `/32`) |

Your Mac does **not** need further configuration, e.g., firewall rules, etc.

## Step 8 — Prove bootstrap SSH

From the Mac, enter the following command with the path to the private key you created in Step 1 and the public IP of the VM:

<Tabs syncKey="pkg">
<TabItem label="dev">
```sh
ssh -i ~/.ssh/example-dev -o IdentitiesOnly=yes ops@159.203.27.69 true
```
</TabItem>
<TabItem label="Template">
```sh
ssh -i ~/.ssh/<project>-<provider> -o IdentitiesOnly=yes ops@xxx.xxx.xxx.xxx true
```
</TabItem>
</Tabs>

It will ask for "Are you sure you want to continue connecting (yes/no)?" - type `yes` and press <Kbd mac="Enter" windows="Enter" />.

If this fails, fix user, keys, or firewall before continuing. Otherwise, it means your VM is accessible via SSH.
