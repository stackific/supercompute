This guide brings up the production environment (aka. **prod**) from your Mac using two public static nodes.

| Host | Role |
| --- | --- |
| **static-1** | Ubuntu 26.04 public endpoint (mesh hub, `x86_64`) |
| **static-2** | Ubuntu 26.04 public endpoint (`x86_64`) |

Optionally, add a roaming node later with [Adding a roaming node](/guides/adding-roaming-node/)—after statics are up.

:::note[Prerequisites]
You have already tried and run [Get started locally](/start-here/get-started/) locally.
:::

### Step 1: Configure prod hosts

Set the `sc_*` FQDNs, then fill public IPs and SSH fingerprints for both static nodes.

For **static-1** and **static-2**, follow [Adding a public node](/guides/adding-public-node/) using the prod key (`~/.ssh/example-prod`). Then come back here.

Edit `inventories/prod/hosts.yml`:

1. Set `sc_ns`, `sc_api`, `sc_app`, and `sc_apps` like below
2. Fill placeholders for **static-1** and **static-2** (public IP and SSH host-key fingerprint)

<Tabs syncKey="pkg">
<TabItem label="prod">

```yaml
---
all:
  vars:
    project: example
    sc_ns: ns.example.com
    sc_api: sc-api.example.com
    sc_app: sc-app.example.com
    sc_apps: sc-apps.example.com

nodes:
  hosts:
    static-1:
      public_ip: "203.0.113.11"
      ssh_ed25519_sha256: "SHA256:pRR...e+M"
      private_address: 10.217.79.11
    static-2:
      public_ip: "203.0.113.12"
      ssh_ed25519_sha256: "SHA256:0f37...2ed230"
      private_address: 10.217.79.12
```

</TabItem>

### Step 2: Configure DNS

Create records matching `sc_ns`, `sc_api`, `sc_app`, and `sc_apps` from Step 1. Leave `example.com` at your registrar. If the DNS is hosted on Cloudflare, do not enable the proxy orange icons.

| Inventory var | Example | Type | Value |
| --- | --- | --- | --- |
| `sc_ns` | `ns.example.com` | A | **static-1** public IPv4 |
| `sc_ns` | `ns.example.com` | A | **static-2** public IPv4 |
| `sc_api` | `sc-api.example.com` | CNAME | `ns.example.com` |
| `sc_app` | `sc-app.example.com` | CNAME | `ns.example.com` |
| `sc_apps` | `sc-apps.example.com` | NS | `ns.example.com` |

Supercompute's Nameserver then serves `*.sc-apps.example.com`.

To use different names, edit those `all.vars` in `hosts.yml`, create matching DNS records, and re-run `task up`.

### Step 3: Initialize the vault

Create the encrypted vault and local password file for prod.

```sh
task vault-init ENV=prod
```

Creates `inventories/prod/.vault-pass` and encrypted `vault.yml` with `vault_meta`, placeholder `vault_database_url`, and auto-generated `vault_database_secret`. The first `task up` adds WireGuard keypairs (and rathole secrets if you add non-Lima roaming hosts).

Decrypted `inventories/prod/group_vars/all/vault.yml` looks like this:

<Tabs syncKey="vault-init">
<TabItem label="prod">

```yaml
---
vault_meta:
  project: example
  provider: prod
vault_database_url: postgresql://REPLACE_WITH_USER:PASSWORD@HOST:5432/DATABASE
vault_database_secret: mT4nQ8pL2vK6wB9xF1hJ5cY0aZ3dE7gH_rXv
```

</TabItem>
<TabItem label="Template">

```yaml
---
vault_meta:
  project: <project>
  provider: <env>
vault_database_url: postgresql://REPLACE_WITH_USER:PASSWORD@HOST:5432/DATABASE
vault_database_secret: <auto-generated at vault-init>
```

</TabItem>
</Tabs>

#### PostgreSQL database

Point the vault at your external Postgres before the first deploy.

Supercompute needs a Postgres database with owner role hosted outside of the Supercompute cloud.

```sh
task vault-edit ENV=prod
```

`task vault-edit` decrypts `inventories/prod/group_vars/all/vault.yml` in your editor. You should see `vault_meta`, `vault_database_url`, and `vault_database_secret` (WireGuard keys appear after the first `task up`). Replace only `vault_database_url` with your connection URI (same shape as the **prod** tab). Leave everything else unchanged.

Example after you set the database URL:

<Tabs syncKey="postgres">
<TabItem label="prod">

```yaml
---
vault_meta:
  project: example
  provider: prod
vault_database_url: postgresql://app:secret@db.example.com:5432/supercompute
vault_database_secret: mT4nQ8pL2vK6wB9xF1hJ5cY0aZ3dE7gH_rXv
```

</TabItem>
<TabItem label="Template">

```yaml
---
vault_meta:
  project: <project>
  provider: <env>
vault_database_url: postgresql://REPLACE_WITH_USER:PASSWORD@HOST:5432/DATABASE
vault_database_secret: <auto-generated at vault-init>
```

</TabItem>
</Tabs>

Save and exit the editor:

- **vim/vi** (default on macOS): press <Kbd mac="Esc" windows="Esc" />, type `:wq`, press <Kbd mac="Enter" windows="Enter" />
- **nano**: press <Kbd mac="Control+O" windows="Control+O" />, <Kbd mac="Enter" windows="Enter" />, then <Kbd mac="Control+X" windows="Control+X" />

`task up` rejects the vault-init placeholder in `vault_database_url`.

### Step 4: Bring up the cloud

Deploy the WireGuard mesh and cluster stack to both static nodes.

```sh
task up ENV=prod
```

When it asks for **BECOME password**, enter your macOS password. You can run `task up` multiple times to retry; it is idempotent.

`inventories/prod/group_vars/all/main.yml` already sets `control_plane: mac`, `provider.platform: public` and Ubuntu 26.04 amd64 (`source: template:ubuntu-26.04`). Change `provider.image.source` only if your provider automation requires a different image identifier.

### Step 5: SSH to the nodes

Confirm you can reach both nodes over the mesh.

```sh
task wg-status ENV=prod
task ssh ENV=prod NODE=static-1
task ssh ENV=prod NODE=static-2
```

Optional latency check from a node to the Mac mesh peer:

```sh
ping -c 10 -I scwg0 10.217.79.1
```

If you can access both nodes, you are done with this guide.

### Checklist

| Item | Done |
| --- | --- |
| `sc_*` FQDNs set in `hosts.yml` | |
| Parent DNS: `sc_ns` A per static + `sc_api`/`sc_app` CNAME to `sc_ns` + `sc_apps` NS (Cloudflare proxy off) | |
| `static-1` + `static-2` public IPs + fingerprints in `hosts.yml` | |
| `~/.ssh/example-prod` on both VMs (`ops` user) | |
| `vault_database_url` set in prod vault (not placeholder) | |
| `ssh … true` works for both static IPs | |
| `task ssh ENV=prod NODE=…` works for both statics | |

### Backup

Store off-repo securely: 

- `~/.ssh/example-prod` (+ `.pub`)
- `inventories/prod/.vault-pass`
- `inventories/prod/group_vars/all/vault.yml`
